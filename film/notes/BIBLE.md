# 《选》制作圣经（所有场景组必读，短）

## 片子是什么
- 抖音竖屏 1080×1920、30 fps、8 分 05 秒。讲姜蓝（网名「自己造船的路飞」）和他写的书《人选天选论》，**正向介绍**（用户原话：对这个人比较信，船肯定是他造的），把书讲清楚。
- 旁白：豆包 TTS 男声「高冷沉稳」，第一人称是 AI（「我是一个AI，这本书三万多字我读完了」）。已配好、已排在 80 BPM 网格上（拍 0.75 s，小节 3 s）。**文案锁定，一字不改。**
- 用户要求：**特别震撼、看起来不像已有技术能做出来的；同时非常易懂、精致**。封面只有一个「选」字。

## 核心视觉（全片统一的「材料」）
**整本书 = 34952 个字 = 34952 个发光的粒子。** 片子里的一切（照片、河、石头、硬币、桥、马蜂、「选」）都可以由这本书自己的字组成、变形、流动；镜头推近时，每一粒都是真的、读得出来的书里的字（宋体）。这是「不像已有技术能做出来」的来源，也是片子的诚实：AI 用这本书本身的字把它讲出来。
- 开场（导演做的 A 场，参考实现 `scenes/s/A.tsx`）：「人选祸/天选福」由全书的字拼成 → 炸开落成整本书的一页（34952 字正好铺满一屏，140 列 × 250 行）→ 镜头扎进序，原文那句道歉在书里亮起来 → 一道光把整本书读一遍 → 所有字飞成一个巨大的「选」。
- **原文句**（scenes.json 里 src 以「原文」开头的句子）：尽量让观众看到这句话**真的在书里**：用 `findInBook()` 找到下标，镜头扎进整页（A 场的做法），或把那几个字从书页里「拔出来」组成引文卡（`Quote`）。别每次都一样，但至少让每个原文句的出处可见（小标签「原文 · 第二章」）。
- **照片底图**：`public/img/*.jpg`（Seedream 生成的写实图，1080×1920，见下表）。用法：照片做背景，字粒子在上面流动/聚合；或者用 `colorFromImage` 让字拼出照片（推近能读，拉远是照片），再淡入真照片。凡是表现真实事件的照片（船厂、出海、翡翠作坊），角落加小标签「AI 示意图」。
- **每个场景至少一个「这怎么做出来的」时刻**，落在重拍或关键词上（导演会按这个验收）。

## 调子
- 温暖、清澈、发光；暖黑底（`Backdrop`）+ 金色字。**不要恐怖**：不要红色警报、闪烁故障、黑屋、吓人的特写（马蜂也要优雅）。
- 色板 `PAL`（`scenes/core/look.tsx`）：gold/goldHi/amber 主色；cream = 白石/贪婪；slate（暗底）/coal（亮底）= 黑石/恐惧；**moon 蓝光只在 E 段和结尾用**；paper = 道痕那一页（H 段是全片唯一的亮色纸面场景）。
- 字体：宋体 `SERIF`（600）/`SERIF_BLACK`（900）做标题和引文，黑体 `SANS` 只给小标签。**DOM 文字要锐利**（大字用 DOM 叠在粒子上，或单独用 DOM）。
- 节奏：画面变化跟着字走（`at('词')`）；大变化落在拍上（`nextBeatF`）。镜头运动要顺（camMix + EASE.inOut），不要抖。

## 版式（竖屏抖音）
- 安全区 `SAFE`：x 64..824，y 340..1480。**必须读的字**（标题、数字、引文、标签）放在里面，中心 x≈444。装饰、粒子、照片铺满全屏。
- 底部字幕由总装统一画（y≈1392，48px）。如果你把某句旁白完整地用大字放在画面上，就把它的 id 写进 `hideSubs`，避免重复。大字别压在 y 1330–1460 的字幕带上（除非那句已 hideSubs）。
- 右上角「• 爽哥说」水印总装统一画，别管。
- 手机上主标题 ≥ 84px，正文 ≥ 44px，小标签 ≥ 30px。

## 规则（违反会坏）
1. **只改自己的文件**：`scenes/s/<ID>.tsx`（可以建 `scenes/s/<ID>/` 子目录放辅助文件）。不要改 core/、Video、registry、别人的场景、public 里已有的文件。需要改公共代码 → 写进你的最终报告，导演来改。
2. 一切由帧号算出：不用 Math.random / Date / requestAnimationFrame / useFrame / setTimeout。随机用 `hash01(i, seed)`、`noise3`、`rnd()`。
3. 每帧只算需要的；重东西（遮罩、取色、排版、目标位置）用 `useMemo` 或 hooks 缓存。34952 个字每帧几个循环没问题（A 场每帧 < 10 ms）。
4. 一个场景最多 2 个 `GlyphCanvas`；`GlyphLayer` 可以多个。
5. 音效只用 `public/sfx/` 里有的（清单 `notes/SFX.md`），音量按建议的下限；配乐已经在大的落点写了重拍，别再叠 boom。
6. 新加的中文字：GB2312 常用字 + 全书 + 文案里的字都有；用生僻字会缺字形 → 别用。
7. 时间只从 `at / atc / lineAt / nextBeatF` 拿，不要写死秒数。场景结束后还会多渲 14 帧给下一场叠化（f >= dur 时保持最后画面）。
8. 场景开头 12 帧会被总装叠化进来（默认 trans: 'fade'），所以第 0 帧就要有完整画面，别从黑场淡入。

## 工作流
- 预览单场：`bash tools/sheet.sh <ID> 15` → `out/sheets/<ID>.jpg`（每 15 帧一张的联系表，带帧号）；看细节：`bash tools/sheet.sh <ID> list 120,300,450`（大图）。**用 Read 看这些 jpg 自检**。
- 完成后：`bash tools/preview.sh <ID>` → 渲带声音的预览，并自动进飞书队列发给用户。
- 进度：每完成一步往 `out/agents/<ID>.status` 追加一行（≤ 30 字，中文），飞书每 10 分钟带上最后一行。
- 类型检查：渲染报错会直接显示；也可以 `cd D:/Projects/writingisthinking/studio && npx tsc --noEmit -p episodes/xuan/tsconfig.json`（如果有）。
- 机器是共享的（13 个场景组同时在做）：渲染并发用脚本里的默认值，别自己开大；联系表优先，完整预览最多 2 次。
